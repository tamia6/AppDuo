# 独立进程名称开关设计

## 目标

克隆默认保留原应用的主进程和辅助进程名称，避免网络规则因进程名变化而失效。只有规则明确允许的应用，才在“网络与存储”中显示“使用独立进程名称”，并由用户按需启用。

## 方案

`Recipe` 增加 `allowIndependentProcessName` 能力字段，规则文件只给微信开启。`CloneConfiguration` 增加持久化的 `useIndependentProcessName`，默认关闭；旧的 `clones.json` 缺失该字段时按关闭读取。

硬分身关闭开关时跳过 `ProcessNames.rename`，启动器（需要启动器时）直接执行原始主程序名。打开开关时保留现有改名流程。软分身不显示该选项，因为它不复制并改写完整应用进程。

本次保留现有 URL 路由实验逻辑，不增加新的朋友圈处理分支；这样可以单独验证进程名是否影响朋友圈跳转。

## 界面与验证

在“网络与存储”中，只有 `recipe.allowIndependentProcessName == true` 且使用硬分身时显示开关，默认关闭。确认页显示当前是否使用独立进程名称。

测试覆盖规则白名单、旧配置兼容、默认保留原进程名、启用后改名，以及未获规则允许时的校验拒绝。构建后重新生成 WeChat 3，实际检查进程名和朋友圈点击结果。
