WeChat is an example, not the only app AppDuo can clone. Choose icons when creating clones. DIRECT is a mainland China exit only if your local network exits there. Configure your own nodes and policy groups; AppDuo does not supply proxies.

Clash / Mihomo routing example

Choose hard clones with the process names above and your preferred display names. Create HK Work and US Work policy groups in your proxy client, then merge these rules.

Place these rules before domain, GEOIP, rule-set or MATCH rules that might match first. The regex covers both the main process and its hyphen-prefixed helpers.

# Merge into your existing configuration; this is not a complete config
mode: rule
find-process-mode: always
rules:
  - PROCESS-NAME-REGEX,^WeChatCN(-|$),DIRECT
  - PROCESS-NAME-REGEX,^WeChatHK(-|$),HK Work
  - PROCESS-NAME-REGEX,^WeChatUS(-|$),US Work
How do I verify routing? What about other proxy clients?

Your client must capture connections and identify local processes. WeChat may ignore the system HTTP proxy; use a mode such as TUN according to your client documentation. Check the process name, matched rule and outbound policy for WeChatCN, WeChatHK and WeChatUS in the connection list.

Other clients with process-name, path or regex rules require their own syntax. This YAML requires Mihomo PROCESS-NAME-REGEX support; it is not universal Clash syntax. A display-name change alone is insufficient. Soft clones use the original process. Environment-variable proxy settings are a separate mechanism and depend on app support.

GOOD TO KNOW

Before you start.

Is the AppDuo app available in English?

The app interface is currently Chinese. This English website and README describe its features; the language setting in AppDuo applies to the cloned app.

Can each clone receive its own notifications?

Yes, compatible clones can receive separate work and personal notifications. Enable notifications in both the app and macOS. Focus mode, running state and third-party versions can affect delivery. Source names and icons depend on app registration; notifications after a clone quits are not guaranteed.

Will it work on my Mac?

Requires macOS 14 or later, on Apple Silicon or Intel. Creating clones requires Apple Command Line Tools. Install them in Terminal with xcode-select --install — no full Xcode installation needed.

Does every app support cloning?

AppDuo includes recipes and automatic detection, but third-party versions vary. Login, multiple instances and notifications need to be tested with your target app.

Will upgrades keep my clone data?

Upgrades preserve data, icons and settings. Update the locally installed source app first, then open AppDuo to check. Quit the clone before upgrading. If the build fails, the existing clone stays intact.

How do I install it?

Download the DMG for your chip and drag AppDuo into Applications, or use the Homebrew command below.

What if macOS blocks the first launch?

Current builds are ad-hoc signed and not notarized by Apple. macOS may warn that the developer cannot be verified or that Apple cannot check for malicious software. Homebrew installs may show the same warning.

After confirming the app came from this project’s GitHub Releases or personal Homebrew tap, and that you trust this source:

  1. Try opening AppDuo in Applications. Dismiss the warning if blocked.
  2. Go to System Settings → Privacy & Security, find the AppDuo warning, and click Open Anyway.
  3. Authenticate if prompted, then click Open. macOS saves an exception for this app.

This does not notarize the app. You do not need to disable Gatekeeper or run Terminal commands to remove quarantine attributes. If the app “will damage your computer” or “is damaged”, stop and download it again from the official release; report an issue if it persists. On a managed Mac, contact your administrator if approval is unavailable.
