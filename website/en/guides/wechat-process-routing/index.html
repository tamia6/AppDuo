Route WeChat clones separately with Mihomo

Use distinct hard-clone process names with Mihomo PROCESS-NAME-REGEX rules, then verify the process, rule and outbound policy.

AppDuo hard clones rename the actual main process. Compatible process-aware proxy clients can use that identity to select separate outbound policies. Changing only a display name or icon is insufficient; soft clones use the original process.

Prepare clones and policies

Create hard clones named WeChatCN, WeChatHK and WeChatUS. In a client using a compatible Mihomo core, create HK Work and US Work policy groups with suitable nodes, or substitute existing groups. AppDuo does not provide proxy nodes.

Merge the rules

This is a configuration fragment. Preserve your existing configuration and avoid duplicate top-level YAML keys. Place these rules before broader domain, GEOIP, rule-set or MATCH rules.

mode: rule
find-process-mode: always
rules:
  - PROCESS-NAME-REGEX,^WeChatCN(-|$),DIRECT
  - PROCESS-NAME-REGEX,^WeChatHK(-|$),HK Work
  - PROCESS-NAME-REGEX,^WeChatUS(-|$),US Work

^WeChatHK(-|$) matches the main process and helpers named WeChatHK-OriginalName, but not WeChatHK2. Match the exact capitalization.

Verify actual routing

  1. Ensure the client captures connections and identifies processes. WeChat may ignore the system HTTP proxy; use a capture mode such as TUN as documented by your client.
  2. Open each clone and generate new connections.
  3. Inspect the process name, matched rule and outbound policy in the connection list.
  4. Expect WeChatCN → DIRECT, WeChatHK → HK Work and WeChatUS → US Work. Existing connections may remain on their previous route.

Troubleshooting

All clones use one exit: check hard-clone mode, process identification, capture mode and earlier matching rules.

Does DIRECT mean mainland China? Only if your local network exits there. DIRECT uses your local connection wherever it is.

Can every Clash client use this? No. This example requires the relevant Mihomo rules. Other clients need their own syntax. AppDuo environment-variable proxies are a separate mechanism that depends on target-app support.
