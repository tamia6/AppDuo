微信分身如何分别走直连、香港与美国节点

使用 AppDuo 的硬分身进程名为不同微信配置 Mihomo PROCESS-NAME-REGEX 规则，并核对实际命中结果。

AppDuo 硬分身会修改实际主进程名，支持进程识别的代理客户端可以据此选择不同出口。仅改显示名称或图标不足以实现分流；软分身仍使用原应用进程。

准备三个硬分身与两个策略组

将三个分身分别命名为 WeChatCN、WeChatHK、WeChatUS。在使用兼容 Mihomo 内核的客户端中创建 HK Work、US Work 策略组并选择节点，或将下例替换为已有组名。AppDuo 不提供节点。

合并规则

下面只是配置片段。不要覆盖现有完整配置，也不要重复创建同名 YAML 顶层字段。把规则放在可能提前命中的域名、GEOIP、规则集和 MATCH 之前。

mode: rule
find-process-mode: always
rules:
  - PROCESS-NAME-REGEX,^WeChatCN(-|$),DIRECT
  - PROCESS-NAME-REGEX,^WeChatHK(-|$),HK Work
  - PROCESS-NAME-REGEX,^WeChatUS(-|$),US Work

^WeChatHK(-|$) 匹配主进程及 WeChatHK-原名称 形式的辅助进程，不会误匹配 WeChatHK2。示例名称大小写必须一致。

验证，而不是只看图标

  1. 让客户端实际接管连接并启用进程识别。微信不一定使用系统 HTTP 代理，应按客户端文档选择 TUN 等接管方式。
  2. 依次打开三个分身，产生新的网络连接。
  3. 在代理客户端连接列表逐一检查进程名、命中规则和出口策略。
  4. 预期 WeChatCN 命中 DIRECT，WeChatHK 命中 HK Work，WeChatUS 命中 US Work。重用的旧连接不一定会立即按新规则重新建立。

常见问题

全部仍然走同一出口：检查是否为硬分身、是否识别到了真实进程、是否有更早的规则命中，以及客户端是否接管流量。

DIRECT 就是国内吗？只有本机网络出口在国内时才是国内直连。海外本机直连仍是海外出口。

其他 Clash 或代理工具能直接复制吗？这份语法针对支持相应规则的 Mihomo 内核。其他客户端需按其文档配置。AppDuo 的环境变量代理是另一种机制，是否生效取决于目标应用。
